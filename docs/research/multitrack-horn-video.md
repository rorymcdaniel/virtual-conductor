# Multitrack horn video with a Pixel 7 and Scarlett 2i2

Research checked 2026-11-23. The target is to record each horn part against a common guide, capture the picture and both mics during the same performance, and replace a few bars of one part while keeping the rest of the arrangement. The paths below assume the Mac used for Virtual Conductor is available. A Mac can host the two USB devices separately. [Google Pixel webcam instructions](https://support.google.com/pixelcamera/answer/14274129) · [Focusrite macOS compatibility](https://support.focusrite.com/hc/en-gb/articles/12033372452754-Focusrite-Compatibility-on-macOS)

Start with **OBS Studio + Shotcut** for a free, open-source path that can preserve both microphone channels. Try **Ableton Live Lite + ZVID Capture** if the Scarlett includes a Live Lite license and a short test confirms the camera follows the audio patch.

## Fully open-source workflow

**OBS Studio + Shotcut** can capture a synced file per part or patch, with more manual assembly. On the Pixel, tap the USB notification and choose **Webcam**. Set up one OBS scene with the Pixel as **Video Capture Device** and the Scarlett as **Audio Input Capture**. Disable any duplicate system or camera audio inputs in OBS. Set **Settings > Audio > Channels** to **Stereo**. In the Scarlett source properties, clear **Enable Downmixing** and explicitly select Scarlett input 1 for **Channel 1** and input 2 for **Channel 2**. This matters especially on 4th Gen, which also exposes loopback inputs. Leave the mixer's separate **Downmix to Mono** control off. Record a short check with input 1 and input 2 heard separately before recording the piece. On Mac, OBS documents Hybrid MOV with PCM for uncompressed audio where the selected output settings support it. This file holds the picture and two audio channels from the same performance. [OBS source project](https://github.com/obsproject/obs-studio) · [Video input](https://obsproject.com/kb/video-capture-sources) · [Audio input](https://obsproject.com/kb/audio-sources/) · [macOS input mapping source](https://github.com/obsproject/obs-studio/blob/master/plugins/mac-capture/mac-audio.c) · [Scarlett 4th Gen inputs](https://focusrite.com/products/scarlett-2i2) · [Stereo and downmix](https://obsproject.com/kb/audio-mixer-guide/) · [Recording formats](https://obsproject.com/kb/hybrid-mp4)

1. Play the same guide with a count-in through the Scarlett headphones for every take. A backing track or a rough recording of the ensemble can serve as the guide. Start OBS before guide playback. For repeatable alignment, play the guide in a separate app, capture that app's audio in OBS, and assign it to its own recording stream. Put the guide file on a reference track in Shotcut. Temporarily select the guide stream in the recorded clip's **Properties > Audio > Track**, then run **Align to Reference Track**. Switch the recorded clip back to the Scarlett stream after it moves into place. Use a guide with distinctive timing or sounds so the alignment can identify the right bars. Mute the reference track before exporting unless it belongs in the final mix. [OBS app audio capture](https://obsproject.com/kb/macos-desktop-audio-capture-guide) · [OBS recording streams](https://obsproject.com/kb/multiple-audio-track-recording-guide/) · [Shotcut clip stream selection](https://forum.shotcut.org/t/audio-video-properties/12923) · [Shotcut alignment](https://forum.shotcut.org/t/timeline-align-to-reference-track/33893)
2. Create one Shotcut video track per part. Use track-level **Size, Position & Rotate** so later replacement clips inherit the same layout. Record only the repair plus some lead-in and tail. Align the pickup to the guide, split the original and the pickup at the same two points, and replace the intervening selection with ripple off. The linked audio travels with the replacement video. If separately adjustable mics are needed, duplicate the audio onto two tracks, use **Copy Channel** to center the left input on one and the right input on the other, and mute the clip's linked audio to avoid duplication. [Shotcut features](https://shotcut.org/features/) · [Shotcut user guide](https://shotcut.org/howtos/Shotcut%20User%20Guide.pdf)

The first hardware check is a short duet with one deliberate two-bar repair. Make a distinct sound at each mic and clap in frame to check the two channels and camera offset in the saved recording. Then export the patched duet and check that both joins sound natural, the repaired tile shows the new performance, and the other part stays in time. The OBS and Shotcut path was verified against documentation and source. The Pixel, Scarlett, and final export still need this end-to-end test. [OBS video delay filter](https://obsproject.com/kb/render-delay-filter/)

An alternative if the phone needs to be untethered or its native camera mode is preferable is to record on the Pixel while recording both mics on the Mac. Clap visibly at the start and end of a longer pass. Align the phone's reference audio with the Scarlett recording and compare the end as well as the start before muting the phone audio. The extra synchronization step repeats for every pickup. [Berklee Online dual-system recording instructions](https://online.berklee.edu/help/en_US/recording-assignments/1964365-advanced-method-how-to-record-video-and-multitrack-audio-of-your-performance-along-with-a-backing-track) · [Shotcut alignment](https://forum.shotcut.org/t/timeline-align-to-reference-track/33893)

## Why zvid alone falls short

zvid is the closest one-app design found. It records a webcam and an audio device onto a source track while the timeline plays, then builds a split-screen from arrangement layers that reference those source tracks. Its guide describes re-recording only the overlap and undoing all edits from a pass. Recording ignores play loops and runs until stopped. [zvid Recording](https://zvid.app/help/recording/) · [Editing](https://zvid.app/help/editing/) · [Layouts](https://zvid.app/help/)

Two issues appeared in automated Chrome tests of web build `158e8f8` using a simulated camera and a stereo WAV fixture:

- **Capture flattened the two inputs.** The stock build acquired one channel and enabled the browser's echo cancellation, automatic gain control, and noise suppression. The resulting Opus stream was mono at 48 kHz. The published bundle leaves stereo and speech processing at browser defaults. Explicit stereo with speech processing disabled produced a two-channel input stream in a temporary test.
- **An in-place repair removed the earlier section.** A short middle recording on the same source track left the new middle and the original tail in place, with the original head blank. Undo restored the full take. This happened with both the stock and explicit-stereo input settings. A different source track for the pickup followed by a manual arrangement-layer edit avoids relying on same-track overwrite, but adds editing steps.

The browser tests did not use the physical Scarlett or the zvid desktop app. Keep the disposable test project short if trying the browser editor, and export it with **Include media files** to keep the media outside browser storage. [zvid project archives](https://zvid.app/help/collaboration/)

## Two-mic capture with a shared recording transport

**Ableton Live 12 Lite + ZVID Capture + zvid desktop** gives Live control of the Scarlett and uses zvid for the picture and layout. Focusrite documents Live Lite as bundled with a Scarlett 2i2 4th Gen. Check the Focusrite and Ableton accounts for an existing license. Existing Live Lite licenses upgrade to 12 for free and do not expire. Lite has eight tracks and supports third-party plug-ins. ZVID Capture supports Live 12 or later and runs on macOS 13+ on Apple silicon. [Focusrite bundle and setup](https://userguides.focusrite.com/hc/en-gb/articles/19640385719570-Setting-up-your-DAW-Recording-Software-with-your-Scarlett-2i2-4th-Gen) · [Live Lite licensing](https://www.ableton.com/en/products/live-lite/) · [Live Lite plug-in support](https://help.ableton.com/hc/en-us/articles/209071589-Live-Lite-FAQ) · [Ableton edition limits](https://www.ableton.com/en/upgrade-live/) · [ZVID Capture requirements](https://zvid.app/help/ableton/)

1. Make one Live Arrangement audio track per horn part. Set **Audio From > Ext. In > 1/2** for each track, so a single stereo source preserves the mic pair. Use Live's metronome or an imported count-in and monitor through wired headphones. Add ZVID Capture to each horn track, choose the Pixel camera, and optionally install its Live companion to start capture via Live's Record control. Arm only the part being played. [Live input and recording](https://www.ableton.com/en/live-manual/12/recording-new-clips/) · [ZVID setup](https://zvid.app/help/ableton/)
2. For a retake, set Live's punch-in and punch-out to the desired bars and start playback a measure or two before the punch-in. Let the camera record a pass that covers the entire replacement. zvid documents matching each Arrangement clip on a capture track to the camera take covering it, preferring the take with the most overlap and then the newest. Validate a first take plus a short patch in a scratch session. A pass starting on the lead-in may tie with the original for the preceding clip, so inspect the imported source clips and correct their selection if needed. [Live punch recording](https://www.ableton.com/en/live-manual/12/recording-new-clips/) · [zvid take matching](https://zvid.app/help/ableton/)
3. Save the Live Set and open its `.als` in zvid desktop. Make a split-screen from the source tracks. The camera files embed AAC from their host track, and Live's effects and devices do not import. For a controlled blend, mix the original 1/2 recordings in Live and export a full-length WAV from the same start as the picture. zvid desktop documents loading a same-named WAV alongside the set as the main audio. Check the mix for duplicate camera sound before export. [zvid Live import and mixdown](https://zvid.app/help/ableton/) · [Mixing and export](https://zvid.app/help/audio/)

CamOrder Studio is an MIT-licensed alternative for someone already using Logic Pro. It records a webcam to video lanes on Logic transport, supports beat-snapped trims, layered framing, and a camera sync adjustment. Its downloadable release is an unsigned Intel development build. The project describes an Apple silicon build from source as unvalidated and calls out transport stalls in silent sections. It captures video separately, so export with sound requires adding a Logic bounce. [CamOrder source and documentation](https://github.com/santismo/CamOrder)

## Phone-only options and when to build

Bandapella is a plausible Android convenience option. Its listing advertises previous-part playback during overdubs, a countdown, split-screen projects, and a waveform editor with splitting and crossfades. The listing does not establish section retakes that replace both the video and audio or separate Scarlett input channels. Focusrite's Android Control 2 app remotely controls an interface connected to a computer. Use the Mac as the USB host for the documented Scarlett support. [Bandapella listing](https://play.google.com/store/apps/details?id=com.bandapella) · [Focusrite Control 2 mobile support](https://support.focusrite.com/hc/en-gb/articles/13208891471250-Which-interfaces-are-compatible-with-Focusrite-Control-2)

If the record-and-repair test exposes too much friction, build a small Mac recorder around the musician's workflow. The first useful slice would be a two-part grid, one camera session, two discrete mic channels, a headphone guide, and a **Replace bars** action with pre-roll. Store original files and use an edit list to switch picture and both mic channels together at the chosen range. Use short audio crossfades and test that both joins sound natural. Camera and audio timing need a measured offset and a drift test across a full-length take. The Virtual Conductor device-selection experience and take-preservation patterns can inform it. The existing capture path serves rehearsal and interpretation and reduces audio to mono, so the new recorder needs its own channel-preserving capture.
